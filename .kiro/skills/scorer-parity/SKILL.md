# Scorer parity

## Rules
- Python defines truth. TypeScript ports it; never the reverse.
- `tests/parity/vectors.json` is generated by `python -m doppelgrund.export.parity`. Never edit it by hand (a hook blocks this).
- Tolerance: 1e-5 absolute on S, coverage and group scores; cards must match exactly (row indices and kinds).

## Workflow
1. Change Python first, with unit tests.
2. Run `make parity` → regenerates vectors, runs `web/tests/parity.test.ts`.
3. If TS fails, port the change. Compare intermediate values case by case: transformed features → z → k → numerators/denominators → S.

## Classic mismatch causes
| Symptom | Cause |
|---|---|
| Off by tiny amounts everywhere | float32 arithmetic in TS; use Float64Array internally |
| NaN vs number on some rows | `isFinite` vs `!isNaN` confusion; `null` not converted to NaN when parsing JSON |
| Cards differ | percentile not using numpy "linear" interpolation; tie-break order; haversine radius not 6371.0088 |
| Lithology off | smoothing order (`lith · C` then normalise) or Hellinger clamp `max(0, 1 − BC)` missing |
| Zero-weight group affects S | group with W = 0 still counted in denominator |

## Adding a case
Add it in `doppelgrund/export/parity.py` with a short `name` describing the edge case; regenerate; both test suites must pass.
